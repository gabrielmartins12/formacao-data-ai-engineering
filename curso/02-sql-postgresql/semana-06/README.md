# Semana 06 — SQL intermediário

**Fase:** 02 sql postgresql  
**Carga estimada:** 8–10 horas  
**Entrega:** Relatório financeiro SQL

## Cenário de negócio

Uma equipe de dados precisa disponibilizar informações confiáveis para análise e tomada de decisão. Nesta sprint, você deverá aplicar **sql intermediário** em um problema realista, utilizando dados sintéticos ou públicos.

## Objetivos de aprendizagem

- Explicar os conceitos: JOIN, CTE, subqueries e window functions.
- Implementar uma solução reproduzível e testável.
- Identificar riscos, limitações e alternativas técnicas.
- Documentar decisões e demonstrar o resultado.

## Aulas da semana

1. **Contexto e teoria (1h30):** estudar JOIN, CTE, subqueries e window functions; registrar definições e exemplos.
2. **Laboratório guiado (2h30):** construir uma versão mínima de **relatório financeiro sql**.
3. **Desafio individual (2h):** acrescentar tratamento de erros, casos extremos e testes sem copiar uma solução pronta.
4. **Projeto integrador (2h):** relacionar o conceito ao FinData AI quando tecnicamente adequado.
5. **Avaliação e revisão (1h):** demonstrar execução, justificar decisões e revisar código.

## Exercícios

1. Explique em suas palavras quando usar os conceitos desta semana.
2. Crie um exemplo mínimo executável e documente as dependências.
3. Adicione pelo menos dois cenários de erro e demonstre como são tratados.
4. Escreva testes ou verificações automatizadas para os requisitos principais.
5. Compare sua solução com uma alternativa e discuta trade-offs.

## Critérios de aceite

- [ ] **Relatório financeiro SQL** funciona com dados de exemplo.
- [ ] Código e instruções de execução estão versionados.
- [ ] Casos inválidos e falhas previsíveis são tratados.
- [ ] Há evidência de testes ou validação.
- [ ] Não há credenciais ou dados pessoais no repositório.
- [ ] Um README explica arquitetura, decisões e limitações.
