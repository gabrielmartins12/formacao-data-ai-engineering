# Metodologia de aulas

## Formato de uma aula (aprox. 2 horas)

1. **Contexto de negócio — 10 min:** quem é o usuário e qual problema resolver?
2. **Teoria — 20 min:** conceitos, alternativas, limitações e trade-offs.
3. **Laboratório guiado — 40 min:** implementação incremental, testes e logs.
4. **Desafio independente — 30 min:** requisito novo sem solução pronta.
5. **Code review — 20 min:** explicação técnica, testes e documentação.

## Distribuição semanal (9 horas)

- Teoria: 1,5 h
- Laboratório: 2,5 h
- Desafio: 2 h
- Projeto integrador: 2 h
- Avaliação: 1 h

## Rubrica de avaliação (100 pontos)

| Critério | Peso |
|---|---:|
| Correção funcional e requisitos | 30 |
| Código, testes e confiabilidade | 25 |
| Fundamentação e decisões técnicas | 20 |
| Segurança e tratamento de falhas | 15 |
| Documentação e comunicação | 10 |

Aprovação sugerida: **70/100**, sem falhas críticas de segurança ou integridade de dados. Notas são atribuídas somente após análise real da entrega.

## Definition of Done

- [ ] Requisitos e critérios de aceite atendidos
- [ ] Testes executados e evidenciados
- [ ] Reprocessamento seguro quando aplicável
- [ ] Sem credenciais nem dados pessoais no Git
- [ ] README atualizado
- [ ] Pull request com descrição e justificativas
